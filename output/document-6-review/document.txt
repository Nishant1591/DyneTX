Detailed WordPress-to-Drupal Migration Analysis Report (Read-Only)


1. Executive Summary
1.1 High-Level Assessment & Critical Verdict
The current DyneTX Drupal implementation has achieved visual rendering parity for marketing page shells, but possesses severe architectural, data-integrity, and editorial defects that prevent it from being production-ready or maintainable:
The "JSON Text Flattening" Anti-Pattern: Instead of modeling the 21 ACF Flexible Content layouts and nested repeaters into proper Drupal Paragraph types and field entities, the current implementation created only 12 Paragraph types and flattened complex nested structures (cards, quotes, team members, table rows, and links) into raw JSON strings stored in text_long fields (field_items_json, field_rows_json, field_sections_json). Content editors cannot edit items using Drupal UI forms without editing raw JSON syntax.
Entity Disconnect and Dual-State Fragmentation: Standalone nodes (job, leader, news) were imported via an ad-hoc PHP script (import-legacy.php), but the primary landing pages (About Us, Careers, Home) display content from hardcoded JSON strings inside Paragraphs, completely disconnected from the entity nodes. Updating a Leader or Job node has zero effect on the landing pages.
Bypassed Core Media System: Drupal Core Media is entirely absent (media table does not exist). The database contains only 27 managed files (file_managed), while over 400 images, PDFs, and video assets are referenced as unmanaged static filesystem paths (/sites/default/files/legacy/...).
Idle and Broken Migration Framework: All four registered Drupal migrate_plus CSV migrations (dyne_pages, dyne_jobs, dyne_leaders, dyne_perspectives) are completely idle with 0 imported records. They target incomplete 8-to-22 row sample CSV files and contain broken schema mappings (e.g. dyne_pages.yml targets page bundle while the site uses dyne_page, mapping title into body).
Zero 301 Redirects: The redirect table contains 0 records. Legacy WordPress URLs dating back to 2014 will trigger 404 errors upon DNS cutover.
Theme Runtime Dependency on Static Disk Fixtures: dynetx.theme executes file_get_contents() on a static JSON file (legacy-page-metadata.json) on every page request to resolve hero banners and CSS body classes, bypassing Drupal entity fields.

4.1 Migration Implementation Patterns in MedicalHub
Intermediate JSON Extraction: Rather than connecting directly to live WordPress MySQL, WordPress content was extracted into structured JSON files (scientific_meeting.json, medical_event.json, medical_resource.json).
Declarative migrate_plus Pipelines: Migration YAML files define explicit source selectors, data types, and transformation process plugins:
entity_lookup: Resolves taxonomy term IDs (field_meeting_year lookup by slug against meeting_year vocabulary).
skip_on_value / skip_on_empty: Prevents duplicate records and halts execution cleanly when foreign keys fail.
migration_dependencies: Enforces strict execution order (e.g. dmc_publications_meeting_year must run before dmc_publications_scientific_meeting).
Core Media Integration: Media entities (media:document, media:image) are generated with managed file IDs (fid) and proper stream wrappers (public://).
URL Redirection Strategy: Script import_redirects.php processes url_mapping.xlsx and creates managed redirect entities.

6. Required DyneTX Content Types and Fields (The Recommended Model)
6.1 Recommended Node Content Types
1. Content Type: Landing Page / Flexible Page (page)
Machine Name: page (replaces non-standard dyne_page)
Purpose: All curated marketing, disease, program, and corporate overview pages.
Fields:
title (Core Title): Page Name.
field_components (entity_reference_revisions -> paragraph, unlimited): References the 21 Paragraph component types.
field_hero_first_line (string, single, optional): Header typography line 1.
field_hero_second_line (string, single, optional): Header typography line 2.
field_hero_third_level (boolean, single, optional, default: 0): Enables compact interior banner.
field_hero_mobile_image (entity_reference -> media:image, single, optional): Mobile portrait crop.
field_hero_overlay_image (entity_reference -> media:image, single, optional): Decorative SVG/PNG overlay.
field_body_class (string, single, optional): Custom body classes for CSS targeting.
2. Content Type: News Article (news)
Machine Name: news
Purpose: Corporate announcements and press releases (populated via GCS Web API sync).
Fields:
title (Core Title): Press release headline.
body (text_with_summary): Full release body HTML.
field_news_date (datetime, single, required): Release publication timestamp.
field_news_type (list_string, single, required, allowed: html|HTML Page, url|External URL, file|PDF Document).
field_external_url (link, single, optional): Hosted GlobeNewswire URL.
field_news_file (entity_reference -> media:document, single, optional): Attached PDF publication.
field_external_id (string, single, required): Unique GCS feed ID (prevents duplicates).
3. Content Type: Career Position (job)
Machine Name: job
Purpose: Open job positions (populated via Greenhouse Harvest API sync).
Fields:
title (Core Title): Position Title.
body (text_with_summary): Role summary, responsibilities, and qualifications.
field_department (entity_reference -> taxonomy_term:department, single, required): Department classification.
field_location (entity_reference -> taxonomy_term:job_location, single, required): Office or Remote location.
field_greenhouse_id (string, single, required): Greenhouse job ID.
field_apply_url (link, single, required): Application submission URL.
4. Content Type: Team Member (team_member)
Machine Name: team_member (replaces ad-hoc leader)
Purpose: Corporate leadership, board of directors, and scientific advisory board profiles.
Fields:
title (Core Title): Full Executive Name.
body (text_with_summary): Executive biography displayed in modal popups.
field_position (string, single, required): Professional title (e.g. "President & Chief Executive Officer").
field_position_info (string, single, optional): Degrees and credentials (e.g. "M.D., Ph.D.").
field_photo (entity_reference -> media:image, single, required): Portrait headshot.
field_team_category (entity_reference -> taxonomy_term:team_category, single, required): Leadership Team, Board of Directors, Founders, SAB.
field_weight (integer, single, default: 0): Presentation sort order.
5. Content Type: Perspective / Patient Story (perspective)
Machine Name: perspective
Purpose: Patient stories, Dynamo employee culture spotlights, and thought leadership articles.
Fields:
title (Core Title): Story headline.
body (text_with_summary): Story content.
field_author (string, single, optional): Author byline.
field_subtitle (string, single, optional): Timeframe or story subhead.
field_story_date (datetime, single, required): Publication date.
field_image (entity_reference -> media:image, single, required): Hero and card thumbnail.
field_disease (entity_reference -> taxonomy_term:disease, single, optional): Disease focus (DMD, DM1, FSHD, Pompe).
field_external_link (link, single, optional): External interview or podcast URL.
6. Content Type: Testimonial / Quote (quote)
Machine Name: quote
Purpose: Employee and patient quotes displayed in carousels and sidebars.
Fields:
title (Core Title): Speaker Name.
field_quote_text (text_long, single, required): Statement text.
field_speaker_image (entity_reference -> media:image, single, optional): Speaker portrait.

8. Migration Mistakes and Missing Implementations
Issue ID: ISS-01
Severity: High
Affected Entity: node:dyne_page vs node:page
File Paths:
web/modules/custom/dyne_migrate/dyne_migrate.install (Line 88)
web/modules/custom/dyne_migrate/migrations/dyne_pages.yml (Line 25)
Current Implementation: dyne_migrate.install defines and populates node bundle dyne_page. However, dyne_pages.yml declares default_value: page.
Expected Implementation: A unified bundle machine name (page). The migration definition must match the active bundle.
Impact: Running drush migrate:import dyne_pages imports records into the wrong bundle (page), creating duplicate or orphan nodes that ignore the dyne_page theme templates.
Correction: Align dyne_pages.yml to target the active landing page bundle, or rename dyne_page to page across all install hooks, displays, and templates.

Issue ID: ISS-02
Severity: Critical
Affected Entity: All Paragraph Types (field_items_json, field_rows_json, field_sections_json)
File Paths:
web/modules/custom/dyne_migrate/dyne_migrate.install (Lines 140–165)
web/themes/custom/dynetx/templates/paragraph--dyne-team-grid.html.twig
web/themes/custom/dynetx/templates/paragraph--dyne-news-list.html.twig
Current Implementation: Complex nested repeaters (cards, leadership bios, news items, pipeline drugs) are encoded as raw JSON strings stored in text_long fields.
Expected Implementation: Structured Drupal sub-fields, nested paragraph types, or dynamic entity references (e.g. field_team_members referencing node:team_member).
Impact:
Content editors cannot edit items through Drupal UI forms without editing raw JSON strings.
Hardcoded unmanaged file paths in JSON bypass Drupal image styles and media tracking.
Complete loss of search indexing and translatability for items inside JSON blobs.
Correction: Refactor the 6 affected paragraph types to use dedicated Drupal field configurations and entity references as defined in §6.2.

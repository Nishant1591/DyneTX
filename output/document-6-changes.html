What changed

The existing Drupal bundles, routes, branded styles and shared team modal are preserved. Native fields now drive hero metadata, taxonomy, publication dates, links and Media. Team profiles, news, quotes, policies and perspective cards use current entity values. Editors no longer need to edit component JSON.

The report’s counts described an earlier state. This work preserved the later 458-node import and added nine reusable quotes and two policy records. All 112 previously unpublished records remain unpublished. The original 64 menu records and 466 aliases are unchanged.

Complete Migrate pipelines now adopt all 458 archive records without duplicate nodes or overwriting later edits. Rollback preserves content and removes migration bookkeeping; database restoration uses the saved backup. Configuration exports contain 822 YAML files in config/sync, with zero differences from active configuration and no pending database updates.

Source interpretation

The 21 ACF definitions are an authoring catalogue. Only nine occur in published source metadata, and some contain older copy than the current page markup. They are now represented by native authoring controls; the current pages were not rebuilt with obsolete content. Custom HTML that WordPress itself stored as page content remains formatted Drupal content. Archived JSON fields and old Paragraph revisions remain available for preservation, but do not drive active structured components.

The site keeps dyne_page and leader machine names. The migration targets these existing bundles instead of renaming them solely to match an example project. Original dynamic layouts and responsive styling continue to render.

Remaining external dependencies

  • 12 newsletter PDFs: absent from the supplied archive and original download locations. Their records are retained; broken or empty replacement files were not created.
  • Live synchronization: Greenhouse and GCS code is implemented, but both providers remain disabled. The local container needs the deployment’s trusted issuer CA for verified outbound HTTPS. GCS also needs an approved client identifier. TLS verification remains enabled.
  • Production infrastructure and OneTrust: Acquia credentials/deployment details and approved production OneTrust collection points were not supplied. No production deployment or form submission was performed.

A read-only, TLS-verified host request validated 41 current Greenhouse jobs and a preview of 39 updates plus two new records. Nothing was queued or published. Fixture and transactional feed tests passed; live GCS execution remains unverified.
